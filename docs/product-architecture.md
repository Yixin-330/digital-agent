# 多模态情境感知数字人产品架构

## 1. 产品定位

本项目面向文化旅游、博物馆、展馆、历史街区、城市漫游与研学等场景，构建一个“用户状态驱动的 AI 服务系统”。

系统不只是被动回答用户问题，而是持续理解用户所处场景、行为状态、兴趣变化和长期偏好，主动生成个性化文化内容、路线规划、互动任务和文创推荐，形成沉浸式、陪伴式、可持续学习的数字人体验。

一句话定位：

> 让数字人从“会聊天的讲解员”升级为“懂场景、懂用户、能主动规划文化体验的智能体”。

## 2. 核心价值

### 2.1 主动式服务

传统导览系统通常依赖用户点击景点、扫码或主动提问。本项目希望通过位置、停留时长、行为轨迹、内容偏好等信号判断用户当前需要什么，并主动触发服务。

典型场景：

- 用户在某展品前停留较久：主动补充深度文化故事。
- 用户连续跳过长篇讲解：切换为轻量化、趣味化表达。
- 用户靠近出口但仍有时间：推荐附近高价值点位或文创商品。
- 用户对某类历史人物表现出兴趣：后续路线和讲解优先关联相关主题。

### 2.2 Context 驱动的实时理解

系统通过 Context 层理解用户当前状态，包括位置、时间、天气、同行关系、访问阶段、停留行为、互动记录、兴趣变化等。

Context 的作用不是简单记录环境，而是为决策提供依据：

- 当前是否适合打扰用户？
- 用户是否正在深入观看某个展项？
- 用户是否需要路线辅助？
- 用户是否更适合听故事、做任务、看图文，还是购买纪念品？

### 2.3 长期 Memory 与用户画像

系统持续沉淀用户长期偏好，形成可更新的 Memory 机制。Memory 不只是保存聊天记录，而是提炼可用于决策的稳定信息。

示例：

- 内容偏好：喜欢历史故事、建筑审美、人物轶事、工艺细节。
- 表达偏好：喜欢简洁讲解、沉浸叙事、问答互动、儿童化表达。
- 行为偏好：喜欢慢游、喜欢打卡、愿意完成任务、倾向购买文创。
- 约束信息：时间有限、体力较弱、带孩子、避开拥挤路线。

### 2.4 一体化体验编排

系统将讲解、推荐、路线、互动、文创转化整合为一个连续体验，而不是多个孤立功能。

用户体验链路：

1. 感知用户进入场景。
2. 判断用户访问目标与当前状态。
3. 推荐合适路线或起始内容。
4. 在关键点位提供个性化讲解。
5. 根据停留和互动触发任务。
6. 根据兴趣和旅程阶段推荐文创。
7. 将本次行为沉淀到长期 Memory。

## 3. 产品角色

### 3.1 终端用户

包括游客、观众、亲子家庭、研学学生、城市漫游用户等。

核心需求：

- 快速理解文化内容。
- 获得适合自己的路线。
- 在有限时间内获得更有价值的体验。
- 通过互动任务增强参与感。
- 获得有意义的文创或纪念推荐。

### 3.2 场馆或景区运营方

核心需求：

- 提升用户停留时长与参与深度。
- 分流人群，优化路线秩序。
- 提高重点展项触达率。
- 提升文创转化。
- 获取用户兴趣与内容运营反馈。

### 3.3 内容运营人员

核心需求：

- 配置景点、展品、故事、任务、文创商品。
- 查看内容表现与用户兴趣。
- 调整推荐策略与触发规则。
- 持续扩充知识库和任务库。

## 4. 核心功能模块

### 4.1 多模态交互层

支持用户通过语音、文本、图像、地图点击、扫码、位置触发等方式与数字人交互。

初期可优先支持：

- 文本问答。
- 语音讲解。
- 位置点位触发。
- 地图路线展示。

后续扩展：

- 图像识别展品。
- AR 导览。
- 表情或动作识别。
- 多人同行识别。

### 4.2 Context 感知层

负责接收并解析实时上下文。

关键输入：

- 用户当前位置。
- 当前时间与访问阶段。
- 停留时长。
- 最近浏览或听取的内容。
- 行为路径。
- 主动提问内容。
- 兴趣反馈。
- 场馆实时状态。

输出：

- 当前场景标签。
- 用户状态判断。
- 可触发服务候选。
- 服务优先级建议。

### 4.3 Memory 与用户画像层

负责沉淀用户长期偏好和短期会话状态。

包括：

- 短期会话 Memory：本次访问中的临时目标、当前位置、最近行为。
- 长期偏好 Memory：跨次访问持续存在的兴趣、表达偏好、消费倾向。
- 场景 Memory：用户在某类文化场景中的行为规律。

### 4.4 决策与推荐层

负责根据 Context、Memory、内容库和业务目标做服务决策。

典型决策：

- 是否主动发起服务。
- 推荐哪个景点。
- 生成哪种讲解风格。
- 规划哪条路线。
- 触发哪个互动任务。
- 推荐哪个文创商品。

### 4.5 Tool Calling 与 Workflow 编排层

数字人通过 Tool Calling 调用外部能力，而不是将所有能力塞进单个模型。

核心工具：

- 景点推荐工具。
- 路线规划工具。
- 文化知识检索工具。
- 讲解生成工具。
- 互动任务触发工具。
- 文创推荐工具。
- 用户画像更新工具。

Workflow 负责把多个工具组织成完整流程。

### 4.6 内容与知识资产层

包括景点、展品、故事、历史人物、文化主题、任务、文创商品等结构化与非结构化内容。

内容类型：

- 景点基础信息。
- 展品说明。
- 文化故事。
- 主题路线。
- 互动任务。
- 文创商品。
- FAQ。
- 多语言内容。

## 5. 典型体验场景

### 5.1 首次进入场馆

用户进入场馆后，系统识别位置与时间，询问或推断用户偏好，生成轻量化访问建议。

输出示例：

- “你大概有 90 分钟，可以走一条历史故事线。”
- “如果你带孩子参观，我可以把讲解变成探索任务。”

### 5.2 点位停留触发深度讲解

用户在某个展品或景点附近停留超过阈值，系统判断其可能感兴趣，主动补充一段个性化讲解。

### 5.3 兴趣驱动路线调整

用户多次对建筑、人物或工艺内容表现出兴趣，系统动态调整后续推荐点位。

### 5.4 互动任务触发

系统根据用户年龄、同行关系、位置和兴趣触发任务，例如寻找某个纹样、回答历史问题、完成路线打卡。

### 5.5 文创推荐

用户在某主题内容上表现出兴趣，系统在合适时机推荐相关文创，而不是生硬售卖。

## 6. 产品成功指标

体验指标：

- 用户停留时长。
- 内容完成率。
- 互动任务参与率。
- 路线采纳率。
- 主动服务接受率。

推荐指标：

- 景点推荐点击率。
- 路线完成率。
- 文创推荐转化率。
- 个性化内容满意度。

运营指标：

- 热点区域分流效果。
- 重点内容触达率。
- 用户复访率。
- 内容更新效率。

## 7. MVP 范围建议

第一阶段不追求完整多模态，而是验证“Context + Memory + Tool Calling”的核心闭环。

MVP 功能：

- 用户文本或语音输入。
- 模拟或基础定位。
- 景点与文化内容知识库。
- 用户短期会话 Memory。
- 简单长期画像。
- 景点推荐。
- 路线规划。
- 个性化讲解。
- 互动任务触发。
- 文创推荐。

MVP 目标：

- 验证主动推荐是否提升用户参与。
- 验证 Memory 是否能改善后续推荐。
- 验证工具编排是否能支撑完整体验链路。
