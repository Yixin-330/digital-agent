# 多模态情境感知数字人：现状分析与演进策略

> 基于完整代码阅读，梳理当前 MVP 的关键短板，给出分阶段演进路径，目标是从"规则驱动的 Demo"进化为"持续学习的个人智能体"。

---

## 一、现状全景评估

### 1.1 当前系统能力评分

| 维度 | 当前状态 | 评分 | 说明 |
|---|---|---|---|
| **多轮对话** | 纯规则 keyword match，无 LLM | ★☆☆☆☆ | `_build_answer` 本质是 FAQ 匹配 |
| **用户画像** | 单次关键词→标签，覆盖 6 个规则 | ★★☆☆☆ | 无法跨 session 积累，无法处理矛盾信号 |
| **短期记忆** | 内存拼接最近 6 轮对话文本 | ★★☆☆☆ | 无结构，无衰减，无重要性排序 |
| **长期记忆** | 纯文本拼接摘要，截断 2000 字 | ★☆☆☆☆ | 线性增长，无压缩无提取 |
| **兴趣图谱** | 用户-主题权重，时间衰减 | ★★★☆☆ | 最简单的 decay 模型，有一定参考价值 |
| **意图识别** | 关键词计数 + Bayes 后验 | ★★☆☆☆ | 无法处理复杂意图、无法泛化 |
| **推荐决策** | 规则模板 + Thompson Bandit | ★★★☆☆ | Bandit 有探索-利用，但 reward 信号弱 |
| **知识图谱** | 5 个节点的静态 JSON | ★☆☆☆☆ | 不是真正的知识图谱，不可持续 |
| **多模态** | `facial_emotion`/`step_rate` 字段定义但未使用 | ☆☆☆☆☆ | 有名无实 |
| **持久化** | 全内存，重启丢失 | ☆☆☆☆☆ | 不可用于真实场景 |
| **A/B 实验** | 简单的 md5 hash 分桶 | ★★☆☆☆ | 无分流记录，无统计显著性检查 |

### 1.2 核心矛盾

**MVP 的定位是「验证闭环」，当前确实验证了：**

- `输入 → 画像 → 意图 → 推荐` 的链路走得通
- Bandit + A/B 的决策框架可运行
- 兴趣衰减模型有一定解释性
- 暖泉古镇的数据结构设计完整

**但它和「越来越懂你的个人智能体」之间的差距在于：**

1. **没有真正的学习机制**——画像不跨 session 积累，兴趣图谱一次会话后即丢失
2. **没有真正的记忆系统**——MemoryStore 只是文本拼接，没有提取、压缩、关联
3. **没有真正的理解能力**——所有"理解"都是关键词映射，语义泛化为零
4. **没有真正的多模态**——多模态字段定义了但全部未消费
5. **没有真正的个性化生成**——推荐是模板填充，不是针对用户的生成式输出

## 三、Phase 1：LLM 接入 + 持久化（2-3 周）

### 目标

把当前规则系统替换为 LLM 驱动，同时解决"重启丢失"问题，让系统在真实场景可用。

### 关键举措

#### 1.1 接入 LLM

将 `_build_answer` 替换为 LLM 调用，同时保留规则作为 fallback：

```python
# 当前：纯规则
def _build_answer(self, message: str, history, guardrails) -> str:
    matched = None
    for faq in self.kb.get("faqs", []):
        if any(token in message for token in faq["q"].split()):
            matched = faq["a"]

# 改进：LLM + RAG + 规则 fallback
def _build_answer(self, message, history, profile, guardrails) -> str:
    if "evidence_required_culture" in guardrails:
        context = self.graph_rag.grounded_answer(message)
    else:
        context = self._retrieve_relevant_context(message)

    prompt = self._build_prompt(
        message=message,
        history=history[-6:],
        profile=profile,
        context=context,
        guardrails=guardrails,
    )
    return self.llm.chat(prompt)  # 调用 Qwen/DeepSeek 等
```

**LLM prompt 结构**（system prompt 的关键组成部分）：

```
你是一个文旅场景的数字人助手，名叫[XX]。
当前用户画像：{travel_style, budget_level, preferences}
当前上下文：{location, weather, visit_stage}
历史摘要：{memory_summary}
安全约束：{guardrails}

回答要求：
1. 基于知识库事实，不编造文化信息
2. 根据用户画像调整语气和信息密度
3. 如果用户没有明确提问，也可以根据场景主动推荐
```

#### 1.2 添加持久化

| 组件 | 当前 | 改进目标 |
|---|---|---|
| Session 记忆 | 内存 | Redis（TTL=1h） |
| 用户画像 | 内存 | PostgreSQL |
| 兴趣图谱 | 内存 | PostgreSQL 或 Redis |
| 事件数据 | 内存 | PostgreSQL 或 ClickHouse |
| 实验分桶 | md5(每次) | Redis 持久记录 |

#### 1.3 升级知识图谱

当前静态 JSON 需要改为真正的图结构，至少支持：

- 节点类型：SPOT / PERSON / EVENT / ITEM / CULTURE_TAG
- 边类型：LOCATED_IN / RELATED_TO / MENTIONED_IN / FOLLOWED_BY
- 属性：置信度、来源、更新时间

这个可以直接复用之前 [记忆图谱改进策略](记忆图谱改进策略.md) 的 mg_node/mg_edge 设计。

## 四、Phase 2：记忆系统 + 跨 session 画像（3-4 周）

### 目标

用户再次使用时，系统能"记得"上次的偏好和行为。

### 关键举措

#### 2.1 三层记忆架构

| 层级 | 存储 | TTL | 内容 |
|---|---|---|---|
| **会话层** | Redis | 会话期间 | 当前对话轮次、最近浏览点位、当前意图 |
| **摘要层** | PostgreSQL | 30 天 | 每次会话结束后生成的摘要（LLM 提炼） |
| **画像层** | PostgreSQL | 永久（可删除） | 稳定的兴趣权重、风格偏好、消费倾向 |

**摘要生成时机**：每次 chat 调用后，LLM 生成结构化的摘要更新：

```python
# 每次 chat 完成后
summary_update = self.llm.extract(
    f"""
    从这次交互中提取结构化信息：
    - 用户表现出的兴趣主题（权重 0-1）
    - 用户表达的约束（时间/预算/体力）
    - 用户对推荐内容的反馈（接受/拒绝/忽略）
    - 需要更新到长期画像的字段
    当前画像：{profile}
    历史摘要：{summary}
    最新对话：{message} → {answer}
    """
)
self.profile_service.merge(user_id, summary_update)
self.memory.append_summary(user_id, summary_update)
```

#### 2.2 画像从"规则标签"升级为"权重向量"

当前画像是一个扁平的字符串字典，需要升级为带权重和置信度的结构化模型：

```python
class PreferenceDimension(BaseModel):
    value: str              # 如 "food", "history"
    weight: float           # 0.0-1.0，多轮积累
    confidence: float       # 0.0-1.0，基于信号数量
    last_updated: datetime
    sources: List[str]      # 证据来源，如 "user_said", "dwell_behavior", "task_completion"

class UserProfileV2(BaseModel):
    user_id: str
    interest_vector: Dict[str, PreferenceDimension]  # "history": {value, weight, ...}
    travel_style: PreferenceDimension
    budget_level: PreferenceDimension
    risk_preference: PreferenceDimension
    interaction_history: List[SessionSummary]  # 最近 N 次 session 摘要
```

**兴趣衰减**：weight 随时间自然衰减，但 confidence 保留（高 confidence = 这个偏好值得保留更久）：

```python
def decay_interest(profile: UserProfileV2) -> UserProfileV2:
    for key, dim in profile.interest_vector.items():
        days_since = (datetime.utcnow() - dim.last_updated).days
        decay_factor = 0.95 ** days_since  # 每天衰减 5%
        dim.weight = max(0.0, dim.weight * decay_factor)
        # confidence 高时衰减更慢
        dim.weight = max(dim.weight, dim.weight * dim.confidence)
    return profile
```

#### 2.3 意图识别升级

当前的关键词计数+Baye 上限明显——无法泛化到训练集之外的意图，也无法处理否定（"我不喜欢历史"）。

升级方案：**LLM 做意图理解，规则做保底**。

```python
def estimate_intent(self, message: str, history, features) -> IntentState:
    # LLM 路径（主路径）
    if self.llm_available:
        return self.llm.parse_intent(message, history, features)

    # 规则 fallback（当前的关键词 + Bayes）
    return self._keyword_intent_fallback(message, history, features)
```

LLM 的意图输出结构：

```json
{
  "primary_intent": "route_plan",
  "secondary_intent": "food_discovery",
  "confidence": 0.85,
  "actionability": "high",
  "extracted_entities": {
    "locations": ["暖泉古镇"],
    "interests": ["非遗", "剪纸"],
    "constraints": {"time": "半天", "companions": "家人"}
  }
}
```

这样 LLM 可以同时提取实体和约束，直接赋能推荐系统。

## 五、Phase 3：多模态感知 + 主动服务（2-3 周）

### 目标

系统能在用户没有主动提问时，根据场景信号主动触发服务。

### 关键举措

#### 3.1 多模态信号接入

当前 ChatRequest 已经定义了但未使用的字段：

| 字段 | 信号含义 | 消费方式 |
|---|---|---|
| `facial_emotion` | 表情识别结果（文字标签） | 影响推荐语气和讲解风格 |
| `step_rate` | 步频（步/分钟） | 判断浏览速度 → 调整内容长度 |
| `venue_id` | 当前所在场馆 | 切换知识库上下文 |
| `location` | 当前位置 | 触发点位相关推荐 |
| `weather` | 天气 | 影响路线推荐 |

**修改**：在 `wenlv_agent_service.chat()` 中真正消费这些信号：

```python
def _adapt_to_emotion(self, emotion: str | None, profile: UserProfile) -> dict:
    """根据表情信号调整回复风格"""
    mapping = {
        "confused": {"tone": "patient", "length": "short", "add_suggestions": True},
        "happy": {"tone": "warm", "length": "normal", "add_engagement": True},
        "tired": {"tone": "gentle", "length": "short", "add_rest_hint": True},
        "surprised": {"tone": "enthusiastic", "length": "normal", "add_detail": True},
    }
    return mapping.get(emotion, {"tone": "normal", "length": "normal"})
```

#### 3.2 主动触发机制

当前系统完全被动（只响应 `POST /chat`）。主动服务需要：

1. **事件监听器**：客户端上报位置、停留等事件 → 服务端判断是否主动触发
2. **触发决策器**：基于规则（同文档中的 context_rules）+ 冷却时间
3. **推送通道**：WebSocket 或 SSE 推送给客户端

```python
# 新增主动服务入口
@app.post("/api/v1/events/location")
def on_location_update(req: LocationEvent):
    context = context_engine.evaluate(req.location, req.dwell_time)
    if should_proactively_serve(context, user_id=req.user_id):
        proactive_service = agent_service.proactive_chat(
            user_id=req.user_id,
            scene_type=context.scene_type,
            user_state=context.user_state,
        )
        return {"proactive": True, "message": proactive_service}
    return {"proactive": False}
```

## 六、Phase 4：持续学习 + 个性化生成（4-6 周）

### 目标

系统能通过每次交互自动改进对用户的理解，生成越来越个性化的内容。

### 关键举措

#### 4.1 从 "特征工程" 到 "表征学习"

当前兴趣图谱的权重更新是手工设计的衰减函数。改进方向：**用用户行为序列训练 Embedding**。

```
当前：hand-crafted decay(weight=weight * 0.92^hours)
改进：user_embedding = f(user_behavior_sequence) → 类比 ItemCF/UserCF 的协同信号
```

第一阶段可以不引入深度学习，而是用**增量式协同记忆**：

```python
class CollaborativeMemory:
    """记录"对主题 X 感兴趣的用户也关注了 Y"的共现关系"""

    def __init__(self):
        self.co_occurrence: Dict[str, Dict[str, int]] = defaultdict(lambda: defaultdict(int))

    def observe(self, user_intents: List[str]):
        """用户在一次交互中表现出的兴趣主题列表"""
        for i in range(len(user_intents)):
            for j in range(i+1, len(user_intents)):
                self.co_occurrence[user_intents[i]][user_intents[j]] += 1

    def related_topics(self, topic: str, top_k: int = 3) -> List[tuple]:
        """给定一个主题，返回用户群体中与之关联最强的其他主题"""
        if topic not in self.co_occurrence:
            return []
        return sorted(
            self.co_occurrence[topic].items(),
            key=lambda x: x[1], reverse=True
        )[:top_k]
```

这个矩阵让系统在冷启动时就能推荐"喜欢 A 的用户也喜欢 B"，不需要深度学习。

#### 4.2 LLM 驱动的个性化生成

当前推荐是模板填充。Phase 4 改为 LLM 基于用户画像 + 知识库生成：

```python
def personalized_recommendation(self, user_id, context) -> str:
    profile = self.profile_service.get(user_id)
    spots = self.venue_data.list_spots(context.venue_id)
    history = self.memory.get_summary(user_id)

    prompt = f"""
    用户画像：
    - 兴趣：{profile.interest_vector}
    - 出行风格：{profile.travel_style.value}
    - 消费倾向：{profile.commerce_preference}

    历史摘要：{history}

    当前上下文：
    - 位置：{context.location}
    - 时间：{context.time_of_day}
    - 已逛点位：{context.visited_spots}

    可选点位：{spots}

    请生成一条个性化推荐，要求：
    1. 从用户最可能感兴趣的点位开始推荐
    2. 给出个性化理由（引用用户画像和历史）
    3. 语气与用户画像中的 style 匹配
    4. 不要编造点位信息
    """

    return self.llm.chat(prompt)
```

#### 4.3 用户模型的隐式反馈学习

当前反馈只有显式的 `click/conversion/dwell`。改进为从**对话内容中提取隐式反馈**：

```python
def extract_implicit_feedback(message: str, llm_response: dict) -> List[Signal]:
    """从用户回复中提取隐式反馈信号"""
    prompt = f"""
    用户消息: "{message}"

    分析用户对之前推荐的反馈（如果没有推荐则返回空列表）：
    - 用户是否接受了推荐？(accepted/rejected/ignored/enthusiastic)
    - 用户对哪些主题表现出了兴趣？
    - 用户提出了哪些约束或修正？
    输出 JSON 格式。
    """
    feedback = llm.parse(prompt)
    return [
        Signal(type=f["type"], topic=f["topic"], strength=f["strength"])
        for f in feedback
    ]
```

这些信号写入兴趣图谱和画像，让用户模型持续更新。

## 七、Phase 5：跨场景泛化（长期）

### 目标

同一个用户，在景区是数字人导游，在电商是智能导购，在社区是内容推荐——但共享同一个用户理解模型。

### 核心设计：统一的用户表示层

```
            ┌─────────────────────────────┐
            │     Unified User Model      │
            │  (兴趣向量 + 风格偏好 +     │
            │   消费倾向 + 信用/信任分)   │
            └──────────┬──────────────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
    ┌──────────┐ ┌──────────┐ ┌──────────┐
    │ 文旅 Agent│ │ 导购 Agent│ │ 推荐 Agent│
    │ (景区导览)│ │ (商品推荐)│ │ (内容推荐)│
    └──────────┘ └──────────┘ └──────────┘
          │            │            │
          ▼            ▼            ▼
    ┌──────────┐ ┌──────────┐ ┌──────────┐
    │ 文旅 KG  │ │ 商品库   │ │ 内容库   │
    └──────────┘ └──────────┘ └──────────┘
```

**关键原则**：

1. **用户模型跨场景共享**——用户在文旅场景表现出的"偏好深度讲解"可以映射到电商场景的"偏好详细参数说明"
2. **场景知识隔离**——文旅 KG 和商品库不混合，Agent 只访问当前场景的知识
3. **行为信号归一化**——所有场景的隐式反馈统一为 `{topic, strength, confidence, context}` 格式

## 八、当前最优先的 5 个改进项

如果资源有限，以下是当前 MVP 最应该优先做的 5 件事（按投入产出比排序）：

### #1 接入 LLM（2-3 天）

**改动最小、效果最明显**。把 `_build_answer` 从 FAQ 匹配改为 LLM 调用，用户感知立刻从"机器人"变为"智能体"。

具体工作：
- 选择一个 LLM 服务（推荐 Qwen/DeepSeek，成本低、中文好）
- 设计 system prompt（包含画像、上下文、安全约束）
- 当前规则降级为 LLM 不可用时的 fallback

### #2 画像持久化 + Redis（2 天）

**解决"重启丢失"的致命问题**。当前所有数据在内存，重启后用户是陌生人。

具体工作：
- ProfileService 接入 PostgreSQL（单表即可）
- MemoryStore 接入 Redis（用户摘要 keyed by user_id）
- InterestGraphService 接入 PostgreSQL（或 Redis sorted set）

### #3 消费多模态字段（1 天）

**零成本提升感知**。ChatRequest 已有 `facial_emotion` 和 `step_rate`，但完全没有使用。

具体工作：
- 在 `_build_answer` 中加入情绪适配逻辑
- 在推荐中加入步频感知（步频快 → 推荐简短内容）

### #4 LLM 做意图提取（2 天）

**取代关键词意图估计，同时获得实体信息**。

具体工作：
- 在 chat 调用中增加一个结构化输出（intent + entities + constraints）
- 将提取的实体传给推荐系统（当前推荐只是基于画像模板匹配，没有消费用户消息中的具体信息）

### #5 冷启动引导（1 天）

**当前冷启动体验差**——用户第一次使用，画像全默认值，推荐完全没有针对性。

具体工作：
- 首次使用时，主动询问 1-2 个问题（"你大概有多少时间？"、"你对什么比较感兴趣？"）
- 根据回答快速建立初始画像，而不是等系统慢慢积累
