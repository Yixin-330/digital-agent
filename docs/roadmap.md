# 项目研发路线图

## 1. 阶段目标

项目建议分为四个阶段推进：

1. 概念验证：验证 Context + Memory + Tool Calling 的核心闭环。
2. MVP 原型：形成可演示的数字人导览体验。
3. 场景试点：接入真实或半真实场馆数据，验证运营价值。
4. 产品化：完善多模态、运营后台、数据分析和稳定性。

## 2. Phase 0：规划与数据准备

目标：明确产品范围、数据结构和演示场景。

交付物：

- 产品架构文档。
- 系统设计文档。
- 用户状态模型。
- Agent Workflow 文档。
- 示例场馆数据。
- 示例用户画像。

建议任务：

- 选择一个具体场景作为样板，如博物馆、历史街区或景区。
- 定义 5 到 10 个核心点位。
- 为每个点位准备基础介绍、故事、标签、推荐理由。
- 准备 3 类用户画像：深度文化型、亲子互动型、轻量打卡型。

## 3. Phase 1：MVP 核心闭环

目标：实现一个可运行的文本版或 Web 版智能导览原型。

核心功能：

- 用户输入当前目标和时间。
- 系统读取或生成用户画像。
- 根据当前位置推荐点位。
- 生成路线。
- 生成个性化讲解。
- 触发简单互动任务。
- 模拟更新用户 Memory。

技术建议：

- 前端：Web 单页应用。
- 后端：FastAPI 或 Node.js。
- 数据：JSON 或 SQLite 起步。
- 检索：本地关键词检索或简单向量检索。
- 模型调用：封装为独立 LLM Service。

验收标准：

- 能完成一次从进入场馆到推荐路线的完整流程。
- 能根据不同用户画像生成不同讲解。
- 能根据用户行为改变后续推荐。
- 至少有 3 个工具调用流程可演示。

## 4. Phase 2：场景化演示版本

目标：形成一个面向汇报或试点展示的完整体验。

核心功能：

- 地图或点位图展示。
- 模拟定位切换。
- 点位停留触发讲解。
- 路线动态调整。
- 互动任务状态管理。
- 文创推荐模块。
- 基础运营配置文件。

交付物：

- 可演示前端。
- 场馆数据配置。
- Workflow 调用日志。
- 用户画像变化可视化。
- 演示脚本。

验收标准：

- 不同用户路径下能产生明显差异化体验。
- 主动服务触发有合理解释。
- 推荐结果能说明“为什么推荐”。
- 文创推荐与文化主题有关联。

## 5. Phase 3：真实试点能力

目标：接近真实场馆或景区试点。

核心功能：

- 真实内容库接入。
- 更稳定的定位或点位识别。
- 用户授权与隐私管理。
- 运营后台。
- 内容审核流程。
- 数据埋点与分析。

重点能力：

- 内容可配置。
- 策略可调整。
- 触发规则可控。
- 用户反馈可分析。
- 模型输出可追踪。

验收标准：

- 运营人员可以维护点位、故事、任务和文创。
- 系统可记录服务触发与用户反馈。
- 支持用户清除或关闭个性化。
- 关键讲解内容有来源依据。

## 6. Phase 4：产品化增强

目标：完善多模态体验和规模化运营能力。

增强方向：

- 语音输入与播报。
- 图像识别展品。
- AR 导览。
- 多语言讲解。
- 多人同行模式。
- 更精细的长期 Memory。
- A/B 测试与推荐策略优化。
- 与票务、会员、商城系统集成。

## 8. 推荐的第一个 Demo

建议第一个 Demo 选择“博物馆沉浸导览”。

原因：

- 点位和内容结构清晰。
- 文化讲解价值明显。
- 用户停留行为容易模拟。
- 互动任务和文创推荐自然。
- 适合展示 Context、Memory 和 Workflow 的完整闭环。

Demo 场景：

```text
用户进入博物馆
  -> 系统询问可用时间和兴趣
  -> 推荐一条主题路线
  -> 用户到达展品 A
  -> 停留较久，触发个性化讲解
  -> 用户追问建筑纹样
  -> 系统更新兴趣
  -> 动态调整后续路线
  -> 触发寻找纹样互动任务
  -> 接近出口时推荐相关文创
```

## 9. 关键风险优先级

P0 风险：

- 内容准确性。
- 用户隐私授权。
- 主动服务打扰。

P1 风险：

- 定位精度不足。
- 用户画像冷启动。
- 推荐解释不足。

P2 风险：

- 多模态交互复杂度。
- 文创推荐过于商业化。
- 运营后台配置成本。
