# 暖泉古镇 P0 数据需求与审查清单

## 1. 数据目标

P0 阶段的数据目标是构建一个“最小可信数据包”，让系统能够完成以下闭环：

1. 根据用户兴趣推荐路线。
2. 根据当前位置触发讲解。
3. 根据停留和偏好触发互动任务。
4. 根据文化兴趣推荐文创或消费服务。
5. 将用户选择沉淀为 Memory 信号。

## 2. 当前已整理的数据

已初步整理到 `app/data/nuanquan_demo_data.json`：

- 场景基础信息。
- 核心点位草案。
- 文化主题。
- 游览路线。
- 互动任务。
- 文创/消费推荐。
- 用户画像样例。
- Context 触发规则。
- 资料来源与待核验字段。

## 3. 点位数据字段

每个点位建议包含：

```json
{
  "id": "spot_xigubao",
  "name": "西古堡",
  "type": "heritage_site",
  "area": "暖泉镇西古堡区域",
  "summary": "一句话介绍",
  "story": "用于讲解的 150-300 字故事",
  "tags": ["古堡", "明清", "古建筑"],
  "suitable_for": ["culture_deep", "photography"],
  "recommended_duration_minutes": 25,
  "trigger_services": ["explanation", "photo_tip", "route_next"],
  "related_products": ["product_papercut_bookmark"],
  "evidence": ["source_xxx"],
  "requires_verification": false
}
```

## 4. 需要你重点审查的字段

### 4.1 点位真实性

请确认：

- 是否适合作为游客可到达点位。
- 是否对外开放。
- 是否需要购票或预约。
- 是否存在更准确的官方名称。

### 4.2 讲解内容准确性

请确认：

- 历史年代是否准确。
- 文保级别是否准确。
- 是否有不适合模型生成发挥的敏感内容。
- 是否需要补充官方来源。

### 4.3 路线可行性

请确认：

- 点位顺序是否符合实际地理动线。
- 预计时长是否合理。
- 是否适合亲子、老人、夜游等不同人群。

### 4.4 运营信息

请确认：

- 打树花表演时间。
- 演出场地。
- 票价和预约方式。
- 文创店和剪纸体验点的真实位置。
- 餐饮、停车、卫生间、休息区位置。

## 5. 优先补充资料

请后续优先补充：

1. 官方导览图或景区地图。
2. 打树花最新演出安排。
3. 当前门票/联票/预约规则。
4. 剪纸体验店或文创店真实名称。
5. 真实游客高频问题。
6. 点位照片或可公开使用图片来源。

## 6. P0 审查建议

建议你按以下顺序审查：

1. 先确认点位清单是否合理。
2. 再确认路线能否实际走通。
3. 再看讲解故事是否准确。
4. 最后审查文创和消费推荐是否自然。

## 7. 数据质量分级

建议给每条数据加质量等级：

- `verified`: 已由官方或可靠资料确认。
- `probable`: 多个资料可交叉支持，但仍需人工确认。
- `demo_only`: 仅用于 Demo 叙事，不可直接上线。
- `dynamic`: 实时变化信息，需要运营后台维护。

## 8. 下一步工程动作

在你审查通过后，可以做三件事：

1. 将 `nuanquan_demo_data.json` 接入推荐服务。
2. 替换当前通用 `culture_kg.json` 和 `knowledge_base.json` 的样例数据。
3. 为 `/api/v1/chat` 增加 `venue_id=nuanquan_ancient_town` 场景参数。
