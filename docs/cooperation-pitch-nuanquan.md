# 暖泉古镇情境感知数字人合作展示说明

## 1. 项目一句话

本项目希望为暖泉古镇构建一个“懂场景、懂游客、能主动服务”的 AI 数字人，通过 Context、Memory、Graph RAG 和 Tool Calling，将文化讲解、路线规划、互动任务和文创推荐整合为连续体验。

## 2. 合作目标

第一阶段目标不是直接上线完整产品，而是先完成一个可演示、可验证、可迭代的概念验证 Demo。

该 Demo 用于回答三个问题：

1. 游客在暖泉古镇中，是否需要一个主动式数字人向导？
2. AI 是否能基于暖泉文化资料提供可信讲解和个性化路线？
3. 文化兴趣是否能自然转化为互动体验和文创消费服务？

## 3. 为什么选择暖泉古镇

暖泉古镇具备非常适合作为 AI 数字人试点的特征：

- 有鲜明文化符号：西古堡、打树花、蔚县剪纸、古街巷、古建筑。
- 有空间漫游需求：游客需要知道怎么逛、先看什么、如何安排夜游。
- 有非遗互动价值：剪纸、打树花和古堡细节适合设计任务。
- 有消费转化场景：文创、纪念品、地方特产可以与文化兴趣自然连接。
- 有持续运营空间：可以通过数据分析优化路线、内容和推荐策略。

## 4. 产品核心能力

### 4.1 情境感知

系统理解用户当前处境：

- 是否第一次到访。
- 是否带孩子。
- 剩余游览时间。
- 当前所在点位。
- 是否对古堡、剪纸、打树花感兴趣。
- 是否接近夜游或表演场景。

### 4.2 可信文化讲解

系统通过 Graph RAG 从暖泉知识图谱中检索内容，再生成讲解，避免纯模型自由发挥。

可讲解内容包括：

- 西古堡。
- 暖泉华严寺。
- 暖泉当铺。
- 打树花。
- 蔚县剪纸。
- 古街巷与民居院落。

### 4.3 个性化路线规划

系统根据用户类型推荐路线：

- 初次到访路线。
- 古建与文化深度路线。
- 亲子非遗互动路线。
- 夜游打树花路线。

### 4.4 互动任务

系统可以在合适位置触发任务：

- 寻找古堡细节。
- 识别剪纸纹样。
- 寻找彩绘元素。
- 古镇商贸线索。
- 记住一朵铁花。

### 4.5 文创与消费服务推荐

系统可根据用户兴趣推荐：

- 蔚县剪纸作品。
- 剪纸纹样书签或小卡。
- 打树花主题纪念品。
- 古堡主题明信片。
- 地方特产组合。

推荐方式强调文化关联和低打扰，不做生硬销售。

## 5. 对景区/合作方的价值

### 5.1 提升游客体验

游客不再只是“看景点”，而是在数字人的陪伴下理解文化、完成任务、形成记忆。

### 5.2 提高文化内容触达率

系统可以把西古堡、剪纸、打树花等重点内容以不同风格讲给不同人群。

### 5.3 增强非遗互动

通过任务化设计，让游客从被动听讲变成主动观察和参与。

### 5.4 带动文创消费

基于游客兴趣推荐文创，解释商品与文化之间的关系，提高推荐可信度。

### 5.5 形成用户关系资产

系统持续沉淀游客偏好，为复访、会员运营、电商推荐和本地消费服务打基础。

## 6. 当前 Demo 已具备的能力

当前已完成：

- 暖泉古镇基础数据包。
- 暖泉点位、路线、任务、文创数据。
- Graph RAG 暖泉知识图谱转换。
- 路线与推荐 API。
- 文化讲解 API。
- 用户画像和基础 Memory 原型。
- A/B、Bandit、安全策略等推荐机制雏形。

当前可演示：

- 用户带孩子首次到访，系统推荐路线。
- 用户询问西古堡，系统给出有来源的文化讲解。
- 用户对剪纸感兴趣，系统推荐非遗任务和文创。
- 用户想看打树花，系统切换夜游路线并提示动态信息需确认。

## 7. 试点阶段建议

### 阶段一：概念验证

周期：2-4 周  
目标：完成可演示 Demo 和合作沟通材料。  
数据：使用当前暖泉 P0 数据，补充少量人工核验内容。

交付：

- Demo 脚本。
- API 演示。
- 合作展示文档。
- 数据补充清单。

### 阶段二：场景化原型

周期：4-8 周  
目标：加入简易前端、地图点位、真实路线和更多内容。  
需要合作方提供：

- 官方导览图。
- 点位开放信息。
- 打树花演出安排。
- 文创店和商品样例。
- 可公开使用的图片素材。

交付：

- 可交互 Web 或小程序原型。
- 暖泉古镇数字人体验流程。
- 内容管理草案。
- 数据埋点方案。

### 阶段三：试点上线

周期：3-6 个月  
目标：在真实场景小范围试点。  
重点补齐：

- 用户授权和隐私机制。
- 真实定位或点位触发。
- 内容审核流程。
- 运营后台。
- 票务、活动、商户数据接口。
- 运行稳定性和安全策略。

## 8. 合作方需要提供的数据

优先级最高：

- 官方点位清单。
- 官方导览地图。
- 西古堡、华严寺、当铺、剪纸、打树花等权威介绍。
- 打树花最新演出时间、票价、预约规则。
- 文创店、剪纸体验点和地方特产信息。
- 可公开使用的图片和视频素材。

可后续补充：

- 游客高频问题。
- 重点推荐路线。
- 人流高峰和分流策略。
- 会员或商城系统对接需求。
- 多语言讲解需求。

## 9. 商业化方向

### 9.1 文旅导览服务

为景区、古镇、博物馆、文化街区提供 AI 导览数字人。

### 9.2 非遗互动体验

将非遗内容任务化、游戏化，提升用户参与和传播。

### 9.3 文创推荐与本地消费

基于用户兴趣推荐文创、特产、餐饮、活动和服务。

### 9.4 用户关系运营

沉淀游客偏好，用于复访提醒、会员运营、二次消费和线上商城推荐。

### 9.5 底层 AI 服务平台

暖泉古镇只是第一个场景。后续同一套 Context + Memory + Trust + Tool Calling 机制可以迁移到电商、本地生活、酒店、餐饮、零售等场景。

## 10. 风险与边界

当前阶段需要明确：

- Demo 数据不等同于上线数据。
- 演出时间、票价、开放状态必须由官方确认。
- 文化内容上线前需要审核。
- 用户数据采集必须有授权。
- 文创推荐应保持低打扰和可解释。

## 11. 合作沟通建议话术

可以这样介绍项目：

> 我们不是只做一个会聊天的讲解机器人，而是希望为暖泉古镇做一个“懂场景、懂游客、能主动服务”的数字人。它可以根据游客是谁、在哪里、想看什么、还剩多少时间，主动推荐路线、讲解文化、触发互动任务，并把游客对剪纸、打树花、古堡等内容的兴趣自然连接到文创和消费服务。第一阶段我们希望先用现有数据完成概念验证，再和景区一起补充真实运营数据，逐步推进试点上线。

## 12. 下一步动作

建议下一步推进：

1. 用现有 Demo 脚本完成一次内部演示。
2. 根据演示结果优化话术和接口返回。
3. 准备一页式项目介绍。
4. 寻找景区、文旅局、运营公司或文创商户进行初步沟通。
5. 获取官方数据后进入场景化原型阶段。
